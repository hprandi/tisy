Projeto: Plataforma de Venda de Ingressos

Visão Geral
A ideia é desenvolver uma plataforma moderna de venda e gestão de ingressos para eventos. O objetivo inicial não é competir diretamente com grandes players do mercado, mas construir um produto simples, utilizando a metologia pareto, real, utilizável e que possa evoluir gradualmente até se tornar um negócio viável.
O projeto será tratado como um produto de verdade, com foco em boa experiência do usuário, arquitetura sólida, qualidade de código e evolução contínua.

Objetivos
O projeto possui dois objetivos principais:

1. Validar uma oportunidade de negócio, criando uma plataforma que possa ser utilizada em um evento real (porém, pequeno e de teste) e que possa evoluir gradualmente para atender eventos maiores.
2. Servir como um projeto de evolução profissional, permitindo que o engenheiro responsável amplie seu escopo além do desenvolvimento Android. O objetivo é adquirir experiência prática em desenvolvimento full-stack, arquitetura de sistemas, infraestrutura, back-end, front-end web e, futuramente, aplicações mobile multiplataforma.

Essa segunda motivação é importante. O projeto deve priorizar tecnologias e decisões arquiteturais que gerem aprendizado relevante e fortaleçam o posicionamento profissional do engenheiro no mercado internacional.

Filosofia do Projeto
O sistema deve ser desenvolvido como se fosse um produto comercial desde o primeiro dia.
Isso significa dar atenção para aspectos como:

* arquitetura limpa e de fácil evolução;
* domínio bem modelado;
* código legível e de alta qualidade;
* testes automatizados quando fizerem sentido;
* documentação das principais decisões arquiteturais;
* observabilidade e facilidade de manutenção;
* deploy e operação próximos de um ambiente real.


O objetivo não é apenas fazer o sistema funcionar, mas construir uma base técnica que demonstre maturidade de engenharia.

Tecnologias Consideradas
A ideia discutida até o momento é utilizar uma stack baseada em TypeScript, por oferecer boa sinergia entre front-end e back-end.
A proposta inicial seria algo próximo de:

* Front-end Web: React (possivelmente Next.js)
* Back-end: Node.js + TypeScript
* Banco de dados: ainda em aberto
* Aplicativo Mobile (em uma etapa posterior): React Native

Essa escolha foi motivada tanto pelo potencial técnico quanto pelo valor para a evolução profissional do engenheiro.
Entretanto, essa decisão ainda não está fechada.
Também foram consideradas alternativas como:

* Flutter para aplicações mobile;
* Go para o back-end;
* outras combinações que façam sentido.

Gostaríamos que este modelo reavaliasse criticamente essa decisão de stack, considerando fatores como:

* qualidade da experiência de desenvolvimento;
* produtividade;
* facilidade de manutenção;
* qualidade arquitetural;
* potencial de aprendizado;
* relevância para o mercado de trabalho nos próximos anos;
* adequação para um produto desse tipo.

Caso existam alternativas mais interessantes, gostaríamos que fossem apresentadas juntamente com os respectivos trade-offs.
